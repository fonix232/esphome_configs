# ESPHome Configurations

## General information

This repo contains my ESPHome configs, split into a logical configuration.

The folder `definitions/` contains, as the name suggests, all definitions, in the following pattern:

- `definitions/mcu` contains barebones MCU configurations, grouped by MCU manufacturer. Where available, different framework bases (e.g. Arduino and ESP-IDF) are broken out into separate configs as well.
- `definitions/board` contains board-specific configurations, also grouped by manufacturer. These configurations import the specific MCU as a package, and expand on it with board-specific additions (e.g. RGB LEDs built onto the board, PSRAM and storage, built-in displays, etc.)
- `definitions/base.yaml` groups base details that all devices share, such as the device name declaration, API, logger, OTA, and other base components
- `definitions/extended.yaml` groups components that represent a heavier load and thus aren't meant for lower end devices due to lack of space or processing power. This currently includes a time component synced from Home Assistant, an uptime sensor, and the full web server in local format.
- `definitions/common` contains split up configurations for the `base` and `extended` packages described above
- `definitions/component` contains external component declarations to simplify sharing basic info between devices (e.g. displays, bluetooth tracker base, other sensors and outputs)
- `definitions/ui` contains basic and specialised UI definitions for all screen sizes. It is a mixture of ESPHome lambdas and LVGL.
- `definitions/devices` contains the fully assembled device descriptors. Such a configuration will usually import a board, and any external components that, connected, make up a fully formed device. This can include extra definitions like I2C, I2S, SPI and other buses.

> [!IMPORTANT]
> To use these definitions, you'll need to check out the repository, then import the specific `device` package with the following substitutions block:
> ```
> substitutions:
> name: "device-name"
> friendly_name: "Friendly Device Name"
> mac_suffix: "DEAD00"
> 
> packages:
>   device: !include definitions/devices/device_definition.yaml
> ```
> You'll have to first flash the device manually, then replace the `mac_suffix` field with the actual suffix generated by the device. After this, the ESPHome dashboard should pick up the device properly.

## Current device definitions

- Air Quality Monitor - utilising a LilyGo T7-S3, a Sensirion SEN55, a battery, and a 128x128 display, this device provides not just raw PM/VOC/NOx readouts, but also broken down AQI indices currently based on the EPA US Air Quality Index charts
- Dongles - these are used all over my home to provide BLE proxying as well as triangulation using the Bermuda integration of Home Assistant
- Tuya SK20 - a galaxy projector of which I have a handful around my home. Pretty straightforward config, albeit with a few features (such as the laser star projector) disabled
